## Why This Section Matters

Organizations and projects are the backbone of the workspace:

- organizations separate workspaces
- projects separate monitoring initiatives inside each workspace

If you skip this structure, the rest of the app will not make much sense.

## Organizations Overview

After login, users are typically redirected to the Organizations page first. This page is the default starting point for most authenticated work.

From here you can:

- view the organizations you belong to
- create a new organization
- edit an existing organization
- delete an organization
- open members and invitations
- open the organization’s projects

## When to Create Separate Organizations

Create separate organizations when you need to isolate work by:

- client
- company
- business unit
- team ownership
- access control

Example:

- One consulting firm with three clients should usually use three organizations.
- One company with several internal monitoring efforts can keep one organization and create multiple projects instead.

## Creating an Organization

Create an organization when:

- you are the first user setting up a workspace
- you need a separate client or department space
- you want separate members, projects, and settings from another workspace

Expect to provide business information such as name, industry, type, size, and country.

## Editing or Deleting an Organization

Organization owners or authorized users can update organization details. Deleting an organization is treated as destructive and prompts for confirmation.

Use edit when:

- the organization name changes
- industry or profile information is outdated
- you need to correct setup data

Use delete only when:

- the workspace is no longer needed
- you are certain the data should be removed

## Organization Profile

The organization profile area gives a broader summary of the organization, including:

- organization details
- plan information
- logo or branding when available
- team member count
- management actions

Use this page as the organization’s “home record” rather than the place where monitoring work happens.

## Members and Invitations

Every organization has a Members & Invitations area. This is where you manage access.

What you can do:

- invite a teammate by email
- assign a role such as Admin, Manager, or Member
- review current members
- update roles
- activate or deactivate members
- remove members
- review invitation statuses
- cancel pending invitations

This makes organizations the right level for access control.

## Invitations Page

There is also a personal Invitations page in the main app where a signed-in user can:

- see invitations sent to them
- accept invitations
- return to the organization list

Use this page if someone has already invited you and you want to join their workspace.

## Projects Overview

Projects live inside organizations. A project represents a distinct monitoring initiative.

Examples:

- EU travel policy updates
- data privacy regulation monitoring
- immigration document requirement tracking
- financial compliance watch

The project list can show:

- project title and description
- number of jurisdictions
- number of sources
- number of revisions or changes
- severity indicators
- last change timing

## Creating a Project

Create a project when:

- the topic, client, or scope is different enough to deserve its own monitoring setup
- different instructions or jurisdictions will be used
- different stakeholders need a clear reporting boundary

A project usually needs:

- a name
- an optional description
- an organization assignment

## Editing or Deleting a Project

Inside a project page, you can usually:

- edit the project name or description
- delete the project
- add a project-level instruction

Project-level instructions help guide monitoring at a broader scope before you get into individual jurisdictions.

## Recommended Project Design

Good project design usually means:

- one project per real monitoring goal
- clear names that non-technical stakeholders can understand
- descriptions that explain what should be tracked

Examples of strong project names:

- Nigeria Data Protection Monitoring
- Canada Immigration Policy Watch
- Regional Tax Compliance Updates

Examples of weak project names:

- Test
- New Project
- Monitor 1
