# Legal WatchDog End-User Manual

This manual is written for people who use Legal WatchDog in the browser. It explains what the app is for, who it is for, and how to complete day-to-day work without referring to the codebase.

Legal WatchDog is a monitoring workspace for teams that need to watch legal, regulatory, policy, and compliance changes across websites, jurisdictions, and organizations. In practice, the app helps you:

- organize work by organization and project
- define jurisdictions to monitor
- add or discover sources for each jurisdiction
- run monitoring and review change analysis
- turn important changes into tickets for follow-up
- manage teammates, invitations, billing, and account settings

## How the App Is Structured

Legal WatchDog has three broad experiences:

1. Public pages: marketing, product information, FAQ, help center, contact, onboarding, and guest access.
2. Main app: the workspace used by regular signed-in users.
3. Super admin console: a separate area for platform operators with access to global reporting, customers, campaigns, and blog tools.

## Typical End-User Journey

For most regular users, the normal flow looks like this:

1. Create an account or sign in.
2. Create or join an organization.
3. Open an organization and create a project.
4. Add one or more jurisdictions inside the project.
5. Write instructions for each jurisdiction.
6. Add sources manually or search suggested sources.
7. Start monitoring.
8. Review analysis and revision history.
9. Open tickets for changes that need human follow-up.
10. Manage teammates, billing, profile details, and invitations as needed.

## Common Use Cases

- A compliance team monitors policy changes across multiple government sites.
- A law firm tracks legal or immigration updates in several countries or regions.
- A consulting team separates work by client organization, then by project.
- An operations team reviews detected changes and creates tickets for escalation.
- A platform administrator reviews customer growth, campaign activity, and platform-wide usage in the super admin console.

## Important Notes

- Projects live inside organizations. You cannot work with projects until you have selected or created an organization.
- Jurisdictions live inside projects.
- The jurisdiction experience is instruction-driven. In most cases, you must save instructions before you can fully use source discovery.
- Some areas of the product are present but still limited in scope. The current UI shows examples such as:
  - Security settings marked as coming soon.
  - API token management that appears to be partially implemented.
- The super admin area is a separate role-based workspace. Most users will never need it.
